## 2. 답변 (holdout2 30문항)

- 30개 모두 답변 생성, 사례 인용 153건 전부 실제 존재하고 질문 조건(업종·재해유형)과 일치
- **지침·법령 질문(N24~N28)**: 사례와 '일반 안전수칙'으로만 답함. 예) N24 "몇 미터부터 추락방지 조치?" → "법적 기준 수치를 확인할 수 없습니다" → V3에서 지침·조문 근거로 개선할 지점
- **이어지는 질문(N29, N30)**: 앞 질문 조건을 이어받음 (N30: 기타의사업 + 끼임 유지) → V2.2에서도 동작
- 사람 블라인드 채점은 V3 답변이 나온 뒤 A/B 순서를 섞어 함께 진행 (지금 채점하면 V2.2 답변을 미리 보게 됨)

## 3. 검색 (retrieval_eval 200개)

| 방식 | Recall@5 | Recall@10 | MRR@10 |
|---|---|---|---|
| 질문 그대로 임베딩 검색 (embed) | 0.395 | 0.445 | 0.304 |
| V2.2 실제 흐름: 질문 이해 → 조건 필터 → 검색 (pipeline) | 0.380 | **0.475** | 0.287 |

정답이 1건이라 비슷한 다른 사례가 위에 와도 오답 → 절대 점수는 낮게 나옴. V3와의 **차이**로 해석한다.

### 발견: 조건 필터가 양날의 검
- 200개 **모두**에 필터가 걸림 (업종+재해유형 166, 재해유형만 34). 질문에 업종이 없는데도 작업 내용으로 업종을 **추측**함
- 그중 **49개(25%)는 정답이 필터에 걸러져 처음부터 찾을 수 없었음**
  - 원인: 업종 추측 오류 35 (예: "사다리에 올라 배관 설치" → 건설업, 실제 제조업) / 재해유형 불일치 12 / 둘 다 2
- 정답이 필터 안에 남은 151개만 보면 Recall@10: embed 0.457 → pipeline **0.629** (+17%p)
- 해석: 필터가 맞으면 크게 도움, 틀리면 정답을 잃음. 떨어짐은 업종이 다양해 pipeline이 오히려 낮음 (0.45 → 0.40)
- V3 검토 방향 (구현 전 결정 기록으로): 질문에 **명시된** 조건만 거르고, 추측한 조건은 거르지 않고 순위에만 반영 / 필터 결과와 필터 없는 결과를 합치기(RRF)

## 4. 응답 시간·비용 (holdout2 30문항, 순차 실행)

| 단계 | 평균 | 비중 |
|---|---|---|
| 질문 이해 (gpt-5.4-mini) | 1.06초 | 24% |
| 임베딩 + 검색 | 0.16초 | 4% |
| 답변 생성 | 3.23초 | 73% |

- 가장 느린 부분은 **답변 생성** → V3 스트리밍으로 첫 글자 시간을 줄이는 근거
- V3는 지침·조문을 프롬프트에 더해 입력 토큰과 답변 시간이 늘 수 있음 → p95 8초, 입력 5,000토큰 목표는 "늘어나도 이 선 안"이라는 의미
- 비용의 절반 이상이 출력 토큰. 프롬프트 캐시 적용 0 (고정 앞부분이 1,024토큰보다 짧음)
- 단가: OpenAI 공식 가격표 2026-11-17 확인 (gpt-5.4-mini 입력 $0.75 / 캐시 $0.075 / 출력 $4.50, 100만 토큰당). 환율 1,400원 가정

## 5. 측정 조건과 한계

- 응답 시간은 내 PC → OpenAI API 기준. V3는 AWS 서버 → API라 네트워크 조건이 다름 → V3 배포 후 같은 스크립트로 서버에서도 측정
- 질문당 입력 토큰 3,897은 V2 기준(3,410, 기존 43문항)보다 큼: 질문 세트가 다르고, V2.2는 조건이 있으면 집계를 추가로 넣기 때문
- 검색 단계 시간은 검색 평가(4개 동시 실행)의 평균으로 추정
- 30문항은 표본이 작아 p95는 사실상 상위 2개 값에 좌우됨
