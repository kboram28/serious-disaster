# V1 답변 관찰 기록

V1 질문 세트 답변을 DB 실제 값과 대조해 확인한 문제점. V2 개선 방향의 근거로 사용한다.

| 질문 | 관찰 | DB 실제 | 원인 |
|---|---|---|---|
| Q31 경기도 끼임 사례 | 서울·대구·전북 사례까지 나열한 뒤 "제외"라고 표시, 최종 1건만 제시 | 경기 끼임 10건 (원본 기준) | 5만 토큰 속에서 조건(지역+유형) 필터를 GPT가 직접 수행 → 누락·혼선 |
| Q32 서울 사례 | 충남 태안·경기 성남 사례를 섞어 제시 | 서울 31건 | 같은 원인 + 지역 표기 혼용(서울/서울시) |
| Q41 건설업 주요 사고 | "떨어짐 다음으로 끼임"이라고 답하고, 끼임 사례로 제조업 사례(313, 321, 323, 331, 353번)를 인용 | 건설업: 떨어짐 157 > 맞음 38 > 깔림 21 > 기타 17 > 끼임 16 > 부딪힘 14 | GPT가 수백 건을 눈으로 세는 방식 → 집계 오류, 업종 혼동 |
| Q22 토사 매몰 대응 | 매몰 사례 275·276·277번을 "재해유형: 끼임"으로 제시 | 원본 라벨 오류 구간 (검증 라벨: 기타/무너짐) | 원본 라벨 오류가 사용자에게 그대로 전달됨 |
| Q21~Q28 사고 대응 | 대응 절차는 GPT 일반 지식으로 작성, 근거 사례·지침 없음 | 데이터에 즉시 대응 정보 없음 | 데이터 한계 |
| Q35~Q40 데이터 밖 | 비슷한 다른 업종 사례로 대체하고 "직접 사례 없음"이라고 밝힘 (정직하나 근거 약함) | 해당 업종 사례 거의 없음 | 데이터 범위가 건설·제조 위주 |

## 분류 오류 패턴 (7건)
- 매몰 → 깔림 (T052, T055): V1은 분류 기준을 모르고 원본 라벨만 참고 → 매몰/깔림 구분 못 함
- 부딪힘 관련 혼동 (T028, T075, T084 등): 부딪힘 사례가 적고(DB 37건 중 다수가 라벨 오류 구간) 기준이 모호

## 정리: V2에서 바꿀 것
1. 조건 필터·집계는 GPT가 아니라 **코드(메타데이터 필터)**로 처리 → 정제된 시도·업종·유형 열 사용
2. 원본 라벨 대신 **검증 라벨** 사용 → 잘못된 유형이 사용자에게 전달되지 않게
3. 분류 기준을 시스템 지시문에 명시 → 매몰/깔림 구분
4. **SIF 6,032건** 추가 → 업종 범위 확대, 재해유발요인·감소대책 제공
5. 사례 전체를 넣지 않고 **관련 사례만 검색해서 전달(RAG)** → 비용·속도 개선, 데이터 확장 가능
