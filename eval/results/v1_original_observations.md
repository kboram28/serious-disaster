# 실제 V1 (졸업작품 원본 로직) 평가 결과

원본 코드를 찾은 뒤(docs/decisions.md [24]) 원본 로직을 `v1_baseline/v1_original.py`로 옮겨 질문 세트 43개로 평가한 결과.
모델은 V2·추측한 V1과 같은 `gpt-5.4-mini`(원본 `gpt-4-turbo`는 서비스 종료), DB는 추측한 V1과 같은 409건.
원본에 분류 기능이 없어 분류 100건 평가는 해당 없음. 원자료: `v1_original_answers.jsonl` (2026-11-19 실행)

## 1. 숫자

| | 실제 V1 | 추측한 V1 (통째로 넣기) | V2 |
|---|---|---|---|
| 사례를 찾은 질문 | **2 / 43** | 해당 없음 (전체 투입) | 43 / 43 |
| 사례 번호를 인용한 답변 | 0% | 98% | 100% |
| 호출당 평균 입력 토큰 | 142 | 49,706 | 3,410 |
| 호출당 평균 출력 토큰 | 55 | 631 | 773 |

- 사례를 찾은 질문: Q30 "건설업 떨어짐 사고는 주로 어떤 작업에서 발생해?", Q43 "제조업에서 끼임 사고가 발생했을 때 어떻게 대처할 수 있어?"
  → 업종과 유형을 모두 **사전에 있는 단어 그대로** 쓴 질문만 통과
- 업종 단어를 찾은 질문 8개, 유형 단어를 찾은 질문 11개. 필터가 AND라 둘 다 찾은 2개만 사례가 나옴
- 응답 시간은 비교에 쓰지 않음: 중앙값 2.0초지만 약 16개가 28~44초로, 동시 실행(4개)에서 생긴 재시도 대기가 포함된 것으로 보임

## 3. 관찰

| 질문 | 뽑힌 키워드 (업종 / 유형) | 결과 | 원인 |
|---|---|---|---|
| Q01 채광창 추락 사고 사례와 예방대책 | 문장 전체 / 떨어짐 | 0건 | 유형은 찾았으나 업종 단어 없음 → 문장 전체로 필터 (버그) |
| Q06 전기 작업 감전 사고 | 문장 전체 / 문장 전체 | 0건 | "감전"이 유형 사전에 없음 |
| Q21 작업자가 비계에서 떨어졌어 | 문장 전체 / 문장 전체 | 0건 | 사전에는 "떨어짐"만 있어 "떨어졌어"를 못 찾음 (활용형 미대응) |
| Q41 건설업에서 주로 어떤 사고가 많이 발생해? | 건설업 / 문장 전체 | 0건 | 졸업작품 시연 질문인데도 유형 단어가 없어 실패 |
| Q42 그럼 어떻게 예방을 미리 할 수 있을까? (Q41에 이어짐) | 문장 전체 / 문장 전체 | 0건 | 키워드를 현재 질문에서만 찾아 이전 대화 조건을 잇지 못함 |
| Q29·Q31·Q32 통계·지역 조건 | 일부 / 문장 전체 | 0건 | 집계·지역 필터 기능 없음 |
| Q30·Q43 | 건설업·제조업 / 떨어짐·끼임 | 5건 요약 | 앞에서 5건만 사용 (관련도 순이 아님) |

- 사례가 0건일 때도 GPT는 지어내지 않고 "구체적인 정보가 확인되지 않았습니다"를 충실히 요약함
  → **실패 원인은 답변 생성이 아니라 검색(사전 키워드 + AND 필터)**
- 인용률 0%는 "간단히 요약해 주세요" 프롬프트 구조 때문 (사례를 찾은 2개도 번호를 붙이지 않음)
- 입력 토큰이 적은 것은 효율이 아니라 사례를 넣지 못했기 때문

## 4. 정리

- 졸업작품 V1의 병목은 **검색**: 사전에 없는 표현·활용형·이어지는 질문에서 사례를 찾지 못함 (95%)
- V2의 핵심 개선이 질문 이해(조건 추출) + 의미 검색 + 대화 맥락 반영인 근거
- 추측한 V1(통째로 넣기)과의 비교는 "검색 없이 전부 넣는 방식"의 비용·조건 필터 한계를 보여주고,
  실제 V1과의 비교는 "키워드 검색 방식"의 재현율 한계를 보여줌
