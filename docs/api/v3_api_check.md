## 1. 국내재해사례 게시판 조회서비스

- 포털: https://www.data.go.kr/data/15121001/openapi.do
- 가이드: `18. 한국산업안전보건공단_국내재해사례 게시판 조회서비스_오픈API활용가이드.docx`
- 주소: `https://apis.data.go.kr/B552468/disaster_api02/getdisaster_api02`
- 고정값: `callApiId=1060`
- 요청 변수: `pageNo`, `numOfRows`, `business`(게시판 종류: 제조업·건설업 등), `keyword`(제목 검색어)

| 응답 필드 | 뜻 | 예 |
|---|---|---|
| `boardno` | 게시판 번호 (고유 ID) | `20261105093815GF3I4H` |
| `business` | 게시판 종류 | 건설업 |
| `keyword` | 제목 | 오수관로 굴착 작업 중 매몰 |
| `contents` | 사고 경위 | 2025. 11. 00. (수) 10시 2분경 경북 안동시 소재 … 하반신이 매몰됨 |
| `atcflcnt` | (가이드에 없음) 첨부파일 수로 추정 | 1 |

가이드와 다른 점
- 가이드는 `http://` → `https://`도 동작 (키 보호를 위해 https 사용)
- `atcflcnt` 필드가 가이드에 없음

관찰
- 날짜·지역 **필드는 없고** `contents` 앞부분에 일정한 형식으로 들어 있음: `YYYY. M. D.(요일) HH:MM경 시도 시군구 소재 …` → 정규식으로 시도·시군구 추출 가능성 높음. SIF(장소 익명화)와 달리 **시군구까지 있음**
- 날짜 일부가 가려진 경우 있음 (`2025. 11. 00.`)
- 내용이 짧음: 원인·예방대책 없음
- `business`가 실제 업종과 다를 수 있음 (예: 영농조합법인 지게차 사고가 건설업 게시판)

V3에서 할 일
- **기존 엑셀(같은 공단 재해사례 정리본)과 중복 확인 필수**, 특히 **테스트 100건과 겹치는 사례는 검색 DB에서 제외** (결정 [6]·[7] 방식)
- 지역은 정규식 추출 → 실패분만 GPT 추출
- 재해유형 라벨은 기존 파이프라인(분류 기준 v2) 재사용

## 2. 기술지원규정(코샤가이드) 조회 서비스

- 포털: https://www.data.go.kr/data/15144147/openapi.do
- 가이드: `11. 한국산업안전보건공단_기술지원규정(코샤가이드) 조회서비스_오픈API활용가이드.docx`
- 주소: `https://apis.data.go.kr/B552468/koshaguide/getKoshaGuide`
- 고정값: `callApiId=1050`
- 요청 변수: `pageNo`, `numOfRows`, `techGdlnNm`(이름), `techGdlnNo`(번호), `ofancYmd`(공표일)

| 응답 필드 | 뜻 | 예 |
|---|---|---|
| `techGdlnNm` | 지침 이름 | 추락방호망 설치 기술지원규정(…) |
| `techGdlnNo` | 지침 번호 (분야-번호-연도) | `A-1-2018`, `A-G-1-2025` |
| `techGdlnOfancYmd` | 공표일 | 2025-03-26 |
| `fileDownloadUrl` | PDF 다운로드 링크 (인증 불필요) | `https://portal.kosha.or.kr/openapi/v1/file/down/…` |

관찰
- **본문은 주지 않음** → PDF를 받아 텍스트 추출해야 함
- 다운로드: `application/pdf`, 파일 시작 `%PDF-1.4`, 텍스트 PDF (OCR 불필요). `Content-Length` 없음. 파일 이름의 한글이 헤더에서 깨짐 → 저장 시 지침 번호로 이름 지정
- 이름 검색 `techGdlnNm=추락` 결과가 **1건**(이름이 "추락"으로 시작하는 것)뿐 → "시작 일치" 검색으로 추정 (미확인)
- 2025년부터 "기술지침" → "기술지원규정", 번호 형식 `A-G-1-2025`

V3에서 할 일
- API 검색에 의존하지 않고 **전체 목록(1,039건, 100건씩 11회)을 받아** 키워드로 거른 뒤 사람이 50~80개 선정
- 선정분 PDF 다운로드 → `pdfplumber` 텍스트 추출 → 장/절 단위 500자 안팎 분할. 선정분 전체가 텍스트 PDF인지 확인

## 3. 국가법령정보 OPEN API

- 신청: https://open.law.go.kr (2026-11-16 신청, 즉시 승인)
- 인증: `OC` = 직접 지정한 인증키, **등록한 공인 IP에서만** 호출 가능 (IP가 바뀌면 마이페이지에서 수정, AWS 배포 시 서버 IP 추가 등록)
- 신청 범위: 현행법령(목록 JSON, 본문 JSON·XML), 현행 행정규칙(목록·본문 JSON)
- 호출은 2단계

| 단계 | 주소 | 주요 변수 | 결과 |
|---|---|---|---|
| 목록 | `https://www.law.go.kr/DRF/lawSearch.do` | `OC`, `target=law`, `type=JSON`, `query=산업안전보건기준에 관한 규칙` | `LawSearch.law[]`: 법령명한글, 법령구분명(고용노동부령), 법령ID `007363`, **법령일련번호 `273603`**, 시행일자 |
| 본문 | `https://www.law.go.kr/DRF/lawService.do` | `OC`, `target=law`, `type=JSON`, `MST=273603` | `법령`: 기본정보, 조문, 부칙, 별표, 개정문, 제개정이유, 법령키 |

조문 구조
- `법령.조문.조문단위[]` 853개 = 장·절 제목(`조문여부=전문`) + **실제 조문 690개**(`조문여부=조문`)
- 필드: 조문번호, 조문제목, 조문내용, 조문시행일자, 조문변경여부, 조문키, 조문이동이전·이후, 항
- 제1조·제2조는 항 없이 `조문내용`에 전체 문장

확인 필요 (수집 단계에서)
- 목록의 시행일자 `20260302`와 본문 기본정보의 시행일자 `20250901`이 다름 → 조문마다 `조문시행일자`가 다를 수 있음. 조문별 시행일자를 함께 저장
- 항·호가 있는 조문(예: ①②)의 구조 확인 → 조문내용 + 항내용 + 호내용을 합쳐 하나의 조문 텍스트로
- 가지 조문(제○조의2) 번호 표기 확인
- `별표`가 본문 응답에 포함됨 (별표서식 API는 신청하지 않음)
