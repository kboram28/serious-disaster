# GPT 기반 중대재해 유형 분류 시스템 — 개선 보고서 (V1 → V2.2)

순천대학교 인공지능공학부 · 권보람, 김세진

---

## 요약

졸업작품으로 만든 "GPT 기반 중대재해 유형 분류 시스템"(V1)을 다시 구축하면서
**데이터 수집·정제 방식과 시스템 구조를 바꾼 개선 버전(V2.2)**을 만들고 같은 조건에서 비교했다.

V1은 두 가지로 비교한다. 처음에는 코드가 유실된 줄 알고 가장 단순한 방식(사례 전체를 프롬프트에 넣기)으로
**추측해 재현**했고(결정 기록 [6]), 이후 졸업작품 백업에서 **원본 챗봇 코드를 찾아** 실제 방식도 같은 조건으로 평가했다([24]).

| 항목 | 실제 V1 (졸업작품 원본) | 추측한 V1 (통째로 넣기 재현) | V2.2 (개선) |
|---|---|---|---|
| 데이터 | 공단 재해사례 엑셀 수작업 정리본 | 같음 | 엑셀 정제·재검증 + **SIF 아카이브 API 자동 수집** |
| 검색 대상 사례 수 | 409건 | 409건 | **6,441건** (16배) |
| 사례당 정보 | 유형·업종·지역·사고내용·예방대책 | 같음 | + **기인물·재해유발요인·연관유형·작업분류·연도** |
| 재해유형 라벨 정확도 | **87.6%** (원본 라벨 오류 12.4%) | 같음 | 사람 검수로 확정 |
| 구조 | 키워드 사전 → 업종 AND 유형 필터 → 앞 5건 요약 | 사례 전체를 매번 GPT에 입력 | 질문 이해 → **코드로 필터·집계** → 의미 검색 → 근거 답변 |
| 사례를 찾은 질문 (43문항) | **2 / 43** | 해당 없음 (전체 입력) | **43 / 43** |
| 분류 정확도 (블라인드 테스트 100건) | 기능 없음 | 93.0% | **97.0%** |
| 질문당 입력 토큰 | 142 (사례를 넣지 못해 적음) | 49,706 | **3,410** |
| 인용 사례가 질문 조건에 맞는 비율 | — (인용 없음) | 84% | **100%** |
| 답변 품질 (사람 블라인드 비교, 16문항) | — | 6승 | **8승** (비슷 2) |
| 사고대응 답변 (사람 블라인드 비교, 새 질문 5문항) | — | — | V2.1 형식이 V2 형식에 **5:0** |

모델은 모두 `gpt-5.4-mini`로 같게 두어, 차이가 **데이터와 구조**에서만 생기도록 했다
(실제 V1의 원래 모델 `gpt-4-turbo`는 서비스 종료).

## 1. 배경: V1과 이번 작업의 목표

V1은 안전보건공단 재해사례를 엑셀로 정리하고, GPT-4(`gpt-4-turbo`) 챗봇이 이를 참고해 사례·예방대책을 답하는 Django 웹이었다.
데이터에는 다음 한계가 있었다.

- 사고 원인, 기인물, 근거 지침이 없음
- 사례 대부분이 건설업 (509건 중 건설업 330건)
- 사고 사진 없음

이번 목표는 **데이터를 자동으로 모으고 필요한 내용을 추출하는 방식으로 바꾸고, 전후를 비교해 왜 바꿨는지 정리하는 것**이다.

처음에는 V1 코드가 유실되고 데이터 전달 방식도 기억나지 않아 **가장 단순한 형태(사례 전체를 프롬프트에 넣는 방식)로 재현**했다 (결정 기록 [6], 이하 "추측한 V1").
이후 졸업작품 백업 zip에서 챗봇 원본 코드(2024-11-28)를 찾아 `v1_original/`에 보관하고,
원본 로직을 그대로 옮겨 같은 질문으로 다시 평가했다 ([24], 이하 "실제 V1"). 남은 원본도 최종 발표본은 아니다.

## 2. V1의 문제 (진단)

### 2-1. 데이터 품질
원본 엑셀 510행을 진단한 결과 (`docs/reports/01_clean_report.md`)

| 문제 | 규모 |
|---|---|
| 번호 없는 행 | 71행 |
| 시도 표기 종류 | 42종 (`경기`/`경기도`, `서울`/`서울시` 등) |
| 지역 사실 오류 | `경기도 삼척시`, `경기도 연천시`, `울산군` 등 |
| 업종 칸 오류 | 끝 공백 73행, 업종 칸에 재해유형 1행 |
| **재해유형 라벨 오류** | **63건 (12.4%)** — 특정 구간에 몰려 있어 라벨 열이 사고내용 열과 구간별로 밀린 것으로 추정 |

라벨 오류는 두 번 독립적으로 확인했다.
- 전체 509건을 GPT 판정 + 사람 검수로 재검증 → 63건 수정 (12.4%)
- 테스트 100건을 사람이 원본 라벨을 보지 않고 다시 분류(블라인드) → 원본 라벨 정확도 89% (오류 11%)

### 2-2. 실제 V1의 한계: 검색이 거의 동작하지 않음 (원본 코드 평가)
`eval/results/v1_original_observations.md`

```
질문 → 동의어 사전으로 업종(8개)·재해유형(6개) 키워드 찾기
     → 엑셀에서 업종 AND 재해유형으로 필터 → 앞에서 최대 5건 → "이 정보를 간단히 요약해 주세요"
```

- 사전에서 키워드를 못 찾으면 **질문 문장 전체를 키워드로 반환하는 버그** → 문장 전체로 필터해 사례 0건
- 결과: 질문 43개 중 **사례를 찾은 질문 2개**. 업종·유형을 모두 사전 단어 그대로 쓴 질문만 통과

| 질문 | 뽑힌 키워드 (업종 / 유형) | 결과 |
|---|---|---|
| 채광창 추락 사고 사례와 예방대책 | 문장 전체 / 떨어짐 | 0건 (업종 단어 없음) |
| 작업자가 비계에서 떨어졌어. 지금 무엇을 해야 해? | 문장 전체 / 문장 전체 | 0건 ("떨어짐"만 사전에 있음) |
| 건설업에서 주로 어떤 사고가 많이 발생해? (시연 질문) | 건설업 / 문장 전체 | 0건 |
| 그럼 어떻게 예방을 미리 할 수 있을까? (이어지는 질문) | 문장 전체 / 문장 전체 | 0건 (이전 대화 조건을 잇지 못함) |

사례가 없을 때 GPT는 지어내지 않고 "정보가 확인되지 않았다"를 요약했다 → **병목은 답변 생성이 아니라 검색**이었다.
분류 기능은 원본 코드에 없었다.

### 2-3. 추측한 V1의 한계: 통째로 넣기 (재현 후 측정)
`eval/results/v1_observations.md`

검색을 없애고 사례 전체를 넣으면 실제 V1의 검색 실패는 사라지지만, 다른 문제가 생긴다.

| 질문 | 추측한 V1 답변 | 실제 데이터 |
|---|---|---|
| 건설업에서 주로 어떤 사고가 많이 발생해? (시연 질문) | "떨어짐 다음은 끼임" + 제조업 사례를 건설업 사례로 인용 | 떨어짐 157 > 맞음 38 > 깔림 21 > 기타 17 > 끼임 16 |
| 경기도에서 발생한 끼임 사고 사례 | 서울·대구 사례를 나열하다 "제외", 최종 1건 | 10건 |
| 굴착 현장 토사 매몰 대응 | 매몰 사례를 "재해유형: 끼임"으로 안내 | 원본 라벨 오류가 그대로 사용자에게 전달 |

원인: 질문마다 사례 409건(약 5만 토큰)을 GPT에 넣고, **조건 필터와 건수 집계를 GPT가 눈으로 수행**했다.
같은 방식으로 SIF 6,032건을 넣으면 모델 입력 한도를 넘으므로 **데이터를 늘릴 수 없는 구조**였다.

상세 내용은 `docs/decisions.md`의 결정 기록 [1]~[13]에 문제 → 선택지 → 결정 → 이유 → 결과 순서로 남겼다.

### 3-1. 데이터

| 결정 | 이유 | 결과 |
|---|---|---|
| [1] 크롤링 대신 **공공데이터 오픈 API** (SIF 아카이브) | 이용 조건이 명확하고, 화면 구조 변경에 영향을 받지 않으며, 원인·대책이 구조화된 필드로 제공됨 | 6,032건 수집 (API 61회 호출) |
| [2] 원본 라벨은 보존하고 **검증 라벨 열 추가** | V1 재현은 원본 라벨로 해야 비교가 공정하고, 무엇을 고쳤는지 추적 가능 | `유형_원본` / `유형_검증` |
| [3] 시도 17개 짧은 이름으로 통일 | 특별자치도 명칭 변경으로 긴 이름은 시기마다 다름 | 42종 → 17종 |
| [4][5][8] **재해유형 분류 기준 문서화** | 원본에는 기준이 없어 같은 사고가 다르게 분류됨 | 아래 3-2 |
| [7] SIF와 엑셀의 중복 확인 | 테스트 사례가 SIF에 있으면 V2 점수가 부풀려짐 | 문장 유사도 최대 0.39 → 같은 사고 없음 |
| [9] 엑셀 사례에서 **기인물·작업·재해유발요인 추출** (GPT, 문장에 적힌 내용만) | SIF와 같은 항목으로 맞추기 위해 | 기인물 미상 4건, 작업 미상 12건 |
| [9] 업종을 SIF 대분류(산재보험 업종)로 통일 | 두 데이터를 하나로 검색하기 위해 | 통합 6,441건 (건설 3,730 / 제조 1,675 / 기타의사업 692 …) |

### 3-2. 재해유형 분류 기준 (사람이 정하고 GPT 판정에 적용)

1. **사람이 입은 피해의 결과**로 분류한다 (물체에 일어난 일로 분류하지 않음)
2. 물체·구조물이 쓰러져 사람이 깔림 → **깔림**
3. 토사·굴착면·건물 붕괴로 **매몰** → **기타(연관: 무너짐)** — 질식 위험, 구조 방법, 예방대책(흙막이 지보공)이 깔림과 다르기 때문
4. 구조물 붕괴로 사람이 떨어짐 → 떨어짐. 단, 떨어진 뒤 중량물에 깔리면 **깔림**
5. 이동하는 차량·장비에 깔림(충돌 후 깔림 포함) → **깔림**
6. 두 가지 이상이면 **가장 큰 원인**, 문장에 없는 내용은 추측하지 않음
7. 원본 6종 체계는 유지하고, **연관유형**(감전·무너짐·익사 등)을 추가해 '기타'의 정보를 보존

SIF 건설업 원래 재해종류와의 일치율은 **90.6%**. 남은 차이는 대부분 기준 차이다
(SIF는 사건 기준 — "갱폼과 함께 떨어짐"을 '낙하', 우리는 결과 기준 — '떨어짐').

### 3-3. 시스템 구조 ([10])

```
질문 → ① 질문 이해 (GPT): 의도(사례·예방/통계/사고대응), 조건(업종·유형·지역), 검색문장
     → ② 조건 필터·집계 (코드): 정제된 열로 정확히 거르고, 건수는 pandas로 계산
     → ③ 의미 검색: 임베딩(text-embedding-3-small) 유사도 상위 8건만 선택
     → ④ 근거 기반 답변 (GPT): 사례 ID 인용 필수, 숫자는 집계값만, 일반 지식은 구분 표시
```

- 이전 대화의 조건을 이어받음 ("그럼 예방은?" → 건설업 조건 유지)
- 사진 입력: 사진 DB 없이, **사진을 GPT가 글로 설명 → 그 설명으로 사례 검색**

### 3-4. 답변 형식 개선 (V2 → V2.1 → V2.2, [11]~[13])

V2 평가에서 사람이 사고대응 질문에 추측한 V1을 선호했다 ("간결 명료해서 긴급상황에 바로 볼 수 있어").
V2는 모든 질문에 같은 형식을 써서 긴급 조치가 뒤로 밀렸기 때문이다.

- V2.1: 의도별 형식 (사고대응은 **"지금 바로 할 일"을 맨 앞에**), 지어낸 사례 ID 차단
- 새 질문 15개로 검증한 결과, **사고대응 형식만 확실한 개선**(사람·GPT 모두 5:0), 나머지 형식 변경은 효과 없음
- 같은 평가에서 **버그 발견**: "가장 많은 재해유형과 예방대책은?"처럼 통계와 예방이 섞인 질문에 집계가 빠짐
- **V2.2 (최종)** = V2 + 사고대응 형식 + 인용 ID 검증 + 조건이 있으면 항상 집계 제공

## 4. 평가 설계 — 공정하게 비교하기 위한 장치

| 장치 | 이유 |
|---|---|
| 실제 V1·추측한 V1·V2 **같은 모델** (`gpt-5.4-mini`) | 차이를 데이터·구조로만 해석하기 위해 |
| **테스트 100건 분리** (유형 비율대로 층화 추출, 시드 고정) — 어느 버전의 DB에도 넣지 않음 | 정답 사례를 그대로 찾아 점수가 부풀려지는 것 방지 |
| 테스트 정답은 **블라인드 라벨링** (원본·GPT 라벨을 가리고 사람이 분류) | 1단계에서 GPT 판정을 미리 채워 두고 검수했을 때 GPT 쪽으로 기우는 편향(앵커링)을 확인했기 때문 |
| 답변 비교는 **A/B 순서를 섞은 블라인드 쌍 비교** | 어느 쪽이 새 버전인지 알면 판단이 기울기 때문 |
| 사람 채점이 끝난 뒤 GPT 채점 공개 | 사람 판단이 GPT 결과에 영향받지 않게 |
| GPT 채점자는 답변 모델보다 **상위 모델** (`gpt-5.5`) | 자기 답 편들기를 줄이기 위해 |
| V2.1은 **고치기 전에 정한 새 질문 15개**로 검증 (테스트 사례에서 무작위 추출) | 약점을 보고 고친 질문으로 다시 재면 점수가 부풀려짐 (과적합) |

## 5. 결과

### 5-1. 재해유형 분류 (테스트 100건, 블라인드 정답)

실제 V1에는 분류 기능이 없어 추측한 V1과 비교한다.

| 지표 | 원본 엑셀 라벨 | 추측한 V1 | V2 |
|---|---|---|---|
| 정확도 | 89% | 93.0% | **97.0%** |
| Macro-F1 | — | 0.871 | **0.950** |
| 부딪힘 F1 (사례가 적은 유형) | — | 0.67 | **0.89** |
| 기타 F1 (매몰·감전 등) | — | 0.82 | **0.95** |

- 추측한 V1이 틀린 매몰→깔림 2건을 V2는 맞힘 (분류 기준 반영)
- V2가 틀린 3건은 모두 블라인드 라벨링 뒤 사람이 다시 조정한, 판단이 애매한 사례

### 5-2. 비용·속도

| | 실제 V1 | 추측한 V1 | V2 |
|---|---|---|---|
| 질문당 입력 토큰 | 142 | 49,706 | **3,410** |
| 분류당 입력 토큰 | 기능 없음 | 49,820 | **1,866** |
| 평가 전체 입력 토큰 | 약 6천 (질문 43개) | 약 712만 | **약 33만** |
| 분류 응답 시간 | 기능 없음 | 3.7초 | **1.1초** |
| 질문 응답 시간 | 측정 제외 (재시도 대기 포함) | 5.6초 | 5.4초 (GPT 2회 호출) |
| 동시 호출 시 속도 제한 오류 | — | 여러 번 발생 | 없음 |

**V2는 데이터가 16배인데 질문당 비용은 추측한 V1의 1/15**이다. 통째로 넣는 방식은 데이터에 비례해 비용이 늘고 결국 입력 한도를 넘지만,
V2는 데이터가 늘어도 질문당 비용이 거의 그대로다. 실제 V1의 토큰이 가장 적은 것은 효율이 아니라 사례를 거의 넣지 못했기 때문이다.

### 5-3. 답변 품질 (기존 43문항)

| 방법 | 실제 V1 | 추측한 V1 | V2 |
|---|---|---|---|
| 사례를 찾은 질문 | **2 / 43** | 해당 없음 (전체 입력) | 43 / 43 |
| 사례 번호를 인용한 답변 | 0% | 98% | 100% |
| 자동 검사: 인용 사례가 질문 조건에 맞음 (조건 있는 9문항) | — | 84% (222/265) | **100%** (59/59) |
| ↳ 경기도 끼임 사고 | 0건 | 11% | 100% |
| ↳ 서울 사고 사례 | 0건 | 40% | 100% |
| GPT 블라인드 비교 (43문항) | 생략 | 16승 | **25승** (비슷 2) |
| **사람 블라인드 비교 (16문항)** | 생략 | 6승 | **8승** (비슷 2) |

실제 V1은 41문항이 "정보 없음" 답변이라 블라인드 비교를 생략했다.

GPT 채점 평균 (1~5점): 정확성 3.84 → 4.14, 근거제시 3.84 → 4.42, 관련성 4.12 → 4.37, 안전성 4.93 → 4.93

### 5-4. 사고대응 개선 검증 (새 질문 15개, V2 vs V2.1)

| 질문유형 | 사람 (V2.1 : V2) | GPT (V2.1 : V2) |
|---|---|---|
| **사고대응 5** | **5 : 0** | **5 : 0** |
| 상황설명 4 | 2 : 2 | 0 : 4 |
| 키워드 3 | 0 : 2 (비슷 1) | 1 : 2 |
| 통계·조건 3 | 1 : 2 | 0 : 3 |

→ 최종 V2.2에는 검증된 사고대응 형식만 채택했다.

### 5-5. 사람과 GPT 채점의 일치율
기존 43문항 비교 **44%**, 새 15문항 비교 **67%**. **GPT 채점만으로 답변 품질을 판단하면 안 된다.**
그래서 이 보고서는 자동 검사와 사람 채점을 주 근거로 쓰고, GPT 채점은 참고로 제시했다.

## 7. 한계와 향후 과제

| 한계 | 내용 | 향후 과제 |
|---|---|---|
| 사고대응의 근거 | "지금 바로 할 일"은 GPT의 일반 응급조치 지식이다 (답변에 '일반 응급조치'로 표시). 데이터에 대응 정보가 없음 | **KOSHA GUIDE**(활용신청 완료)를 연결해 공식 지침 근거로 제시 |
| 지역 정보 | SIF는 장소가 익명화되어 지역 검색은 공단 재해사례(6%)에만 가능 | 공단 재해사례 API(활용신청 완료)로 최신 사례와 지역 보강 |
| 법규 근거 | 예방대책에 관련 조항(산업안전보건기준규칙)이 연결되지 않음 | KOSHA GUIDE·법령 조항 매핑 |
| SIF 라벨 | 6,032건은 GPT 판정(사람 검수 없음). 원래 유형과 일치율 90.6% | 불일치 사례 표본을 사람이 검수해 오류율 측정 |
| 평가 규모 | 사람 채점은 16+15문항으로 작음. 사고대응 개선(5:0)도 5문항 기준 | 현장 사용자 피드백(웹 화면에 저장됨)으로 지속 평가 |
| 사진 기능 | 정량 평가를 하지 않음 (사진 데이터셋 없음) | 공개 건설현장 이미지 데이터로 평가 |
| 개선 결정의 검증 | V2.2의 "일반 형식 되돌림"과 "통계 버그 수정"은 새 질문 15개를 보고 내린 결정이라 같은 질문으로 성능을 다시 잴 수 없음 | 또 다른 새 질문으로 V2.2 재평가 |
