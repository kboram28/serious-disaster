# GPT 기반 중대재해 유형 분류 시스템 — 재구축 진행 순서

> 목표: 기존 방식(V1)을 재현하고, 공공데이터 API로 데이터를 보강한 개선 버전(V2)을 만든 뒤
> 두 버전을 같은 기준으로 비교하여 **무엇을, 왜 수정했는지**를 수치로 정리한다.

---

## 전체 흐름

```
0. 준비 → 1. 정제·진단 → 2. V1 재현(기준) → 3. SIF 수집 → 4. V2 구축 → 5. 비교 평가 → 6. 웹 UI → 7. (선택) 확장
```

| 단계 | 내용 | 결과물 |
|---|---|---|
| 0 | 준비 (엑셀, API 키) | `data/raw/`, `.env` |
| 1 | 기존 데이터 정제·진단 | `cases_clean.csv`, 진단 리포트 |
| 2 | V1 재현 + 평가셋 고정 | V1 코드, 평가셋, V1 점수 |
| 3 | SIF 데이터 수집 | SIF 원본, 필드 분석 메모 |
| 4 | V2 구축 | 통합 데이터셋, 검색·분류·답변 모듈 |
| 5 | V1 vs V2 비교 평가 | 비교표, 그래프 |
| 6 | 웹 UI | Streamlit 데모 |
| 7 | (선택) KOSHA GUIDE 등 확장 | V2+GUIDE 비교 |

---

## 0단계. 준비

- [ ] 원본 엑셀을 `data/raw/`에 넣기
- [ ] 공공데이터포털에서 **SIF 데이터 파일(엑셀/CSV) 다운로드** → `data/raw/sif/`에 저장
  - 파일 데이터는 키 없이 내려받을 수 있음 (API는 필요 시에만 사용)
  - 참고: [SIF 아카이브 조회서비스(API)](https://www.data.go.kr/data/15161362/openapi.do)
- [ ] 프로젝트 루트에 `.env` 생성
  ```
  OPENAI_API_KEY=...
  ```

---

## 1단계. 기존 데이터 정제와 진단

**할 일**
- 지역 표기 통일 (`서울시`/`서울`, `경상남도`/`경남`, `인천시`/`인천광역시` 등)
- 오타·오류 수정
  - 오타: 중락구, 안상시, 청북, 충천남도, 서상시
  - 사실 오류: 경기도 삼척시 → 강원, 경기도 연천시 → 연천군, 울산군 → 울산광역시
  - 필드 오류: 201번 업종 칸의 `떨어짐`
- 번호 없는 행(약 85건)에 번호 부여
- 사고내용 ↔ 예방대책 행 정렬 확인

**진단 항목 (V1의 한계를 수치로 기록)**
- 원인·즉시대응·근거 필드 채움률 (현재 0%)
- 업종별·유형별 분포 (건설업·떨어짐 쏠림)
- 총 사례 수

**결과물**: `data/processed/cases_clean.csv`, 데이터 진단 리포트

---

## 2단계. V1 재현 (비교 기준)

**할 일**
- 포스터 구성대로 최소 재현: 엑셀 데이터 + GPT 질의응답 + 단순 검색
- **평가셋 고정** (이후 V1·V2 모두 같은 평가셋 사용)
  - 유형 분류 테스트 사례 (정제 데이터에서 일부 분리)
  - 고정 질문 30~50개 (키워드, 상황 설명, 예방대책 문의 등)

**결과물**: `v1_baseline/` 코드, `eval/` 평가셋, V1 점수

> V1을 먼저 만드는 이유: 비교 기준이 있어야 개선 효과를 수치로 보여줄 수 있음

---

## 3단계. SIF 데이터 수집

**할 일**
- 다운로드한 SIF 파일을 가공 없이 `data/raw/sif/`에 보관하고, 파일명에 다운로드 날짜 기록 (재현성 확보)
- 수집 스크립트는 "파일 읽기 → 표준 형식 변환"으로 작성 (파일이 갱신되면 재실행만 하면 되도록)
- 실제 필드 분석
  - 사고개요, 기인물, 고위험작업/상황, 재해유발요인, 위험성 감소대책이 어떻게 들어 있는가
  - 원인 서술이 얼마나 구체적인가
  - 관련 법규·지침(**KOSHA GUIDE 번호**) 정보가 있는가
  - 건수, 업종 분포 (공개 자료 기준 2016~2023년 약 6,000건)

**판단 포인트**
- SIF에 GUIDE 정보가 충분 → KOSHA GUIDE API 생략
- 부족 → 7단계에서 KOSHA GUIDE 추가

**결과물**: SIF 원본 데이터, 필드 분석 메모

## 4단계. V2 구축

**4-1. 통합 스키마로 병합**

| 필드 | 예시 | 출처 |
|---|---|---|
| 재해유형 | 떨어짐 | 원본 |
| 업종 / 지역 | 건설업 / 경기 고양시 | 원본(표준화) |
| 작업종류 / 기인물 / 장소 | 철거 / 채광창 / 축사 지붕 | GPT 추출 |
| 높이·규모 | 6.5m | GPT 추출 |
| **직접원인 / 간접원인** | 채광창 덮개 미설치 / 작업계획 미수립 | SIF 또는 GPT 추출 |
| **즉시 대응** | 119 신고, 2차 추락 방지 | 근거 기반 생성 |
| 예방대책 | 30cm 이상 작업발판 설치 | 원본, SIF |
| **근거** | 산업안전보건기준규칙 조항, KOSHA GUIDE 번호 | SIF |
| 출처 / 수집일 | SIF, 2026-10-17 | 자동 기록 |

굵은 필드 = 기존 엑셀에 없던 항목 (개선 비교의 핵심)

**4-2. GPT 필드 추출**
- JSON 형식 출력으로 스키마 필드 추출
- 일부 표본은 사람이 직접 검수하여 추출 정확도 기록

**4-3. 검색·답변**
- 임베딩 → 벡터DB (Chroma 또는 FAISS)
- 메타데이터 필터(유형, 업종, 기인물) + 유사도 검색
- 답변 시 근거 사례·법규 인용

**4-4. 사진 입력**
- 비전 모델로 사진을 텍스트 설명으로 변환 → 그 설명으로 사례 검색
- 사고 사진 DB 없이도 사진 기능 구현 가능

**결과물**: `data/processed/cases_v2.csv`, `pipeline/` 모듈

## 5단계. V1 vs V2 비교 평가

같은 평가셋으로 측정한다.

| 지표 | 측정 방법 |
|---|---|
| 데이터 품질 | 필드 채움률, 업종 분포, 총 사례 수 |
| 분류 정확도 | 재해유형 예측 정확도, 유형별 F1 |
| 검색 품질 | 고정 질문의 Hit@5 (상위 5건에 관련 사례 포함 비율) |
| 답변 품질 | 정확성·구체성·근거 제시 1~5점 (사람 채점 + GPT 보조) |
| 근거 인용률 | 답변에 출처가 포함된 비율 |

**결과물**: 비교표, 그래프, `eval/results/`

## 6단계. 웹 UI

Streamlit으로 포스터의 기능 4가지 구현
- 대화형 챗봇 (RAG)
- 사진·파일 업로드 및 분석
- FAQ / 기인물별 가이드라인
- 답변 피드백(좋아요/싫어요) 저장

**결과물**: `app/` 데모 웹
