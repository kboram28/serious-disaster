# 결정 기록

V1(기존) → V2(개선)로 가면서 내린 결정과 그 이유를 기록한다. 최종 보고서의 "개선 배경" 장으로 사용한다.

### [1] 추가 데이터 수집 방식: 크롤링 대신 공공데이터 API

- 문제: 기존 엑셀(공단 재해사례 정리본)에 사고 원인, 기인물, 근거가 없고 건설업 사례에 쏠려 있음
- 선택지
  1. 공단 포털 웹 크롤링
  2. 공공데이터포털 파일 다운로드
  3. 공공데이터포털 오픈 API
- 결정: 3번 오픈 API (SIF 아카이브 조회서비스)
- 이유
  - 이용 조건이 명확함 (이용허락범위 제한 없음, 무료)
  - 크롤링은 사이트 화면 구조가 바뀌면 코드가 깨지고, 이용약관 문제가 생길 수 있음
  - 파일은 갱신될 때마다 직접 다시 받아야 하지만, API는 수집 코드를 다시 실행하면 됨 → "자동 수집" 목표에 맞음
  - 기인물, 고위험작업·상황, 재해유발요인, 위험성 감소대책이 구조화된 필드로 제공됨
- 결과: 6,032건 조회 가능 확인 (건설업 3,459 / 전업종 2,573)
- 남은 과제: 법규·지침 필드가 없음 → KOSHA GUIDE 연결 검토

### [2] 기존 엑셀의 재해유형 라벨 오류: 원본 보존 + 재검증 열 추가

- 문제: 사고 내용의 핵심 단어와 재해유형 라벨이 맞지 않는 행이 51건. 특정 구간에 몰려 있음
  (예: 엑셀 351~358행은 모두 "끼여 사망"인데 라벨은 `떨어짐`).
  사고내용·예방대책은 서로 일치 → 라벨 열(유형·업종·지역)이 구간별로 밀린 것으로 추정
- 영향: 이 라벨을 정답으로 쓰면 분류 정확도 평가가 틀어지고, 업종·지역도 틀렸을 가능성이 있음
- 선택지
  1. 원본 라벨을 그대로 사용
  2. 원본 라벨을 덮어써서 수정
  3. 원본은 보존하고 재검증 라벨 열을 따로 추가
- 결정: 3번
- 이유: V1 재현은 원본 라벨로 해야 공정한 비교가 되고, 무엇을 왜 고쳤는지 추적할 수 있음
- 진행: 키워드 규칙으로 의심 행 표시(`라벨의심`) → GPT 재판정 + 사람 검수로 `유형_검증` 생성 예정.
  업종·지역은 공단 재해사례 API 원문과 대조해 복원 예정

### [3] 지역 표기: 시도 17개 짧은 이름으로 통일

- 문제: 시도 표기가 42종 (`경기`/`경기도`, `서울`/`서울시`, `인천시`/`인천광역시` 등), 오타·사실 오류 포함
- 결정: `서울`, `경기`, `강원` 같은 17개 짧은 이름 + 시군구 열 분리
- 이유: 강원·전북·제주는 특별자치도로 명칭이 바뀌어 긴 이름은 시기마다 달라짐. 짧은 이름은 SIF 등 다른 데이터와 맞추기도 쉬움
- 결과: 시도 표기 42종 → 17종. 오타·오류 10종 수정 (중락구→중랑구, 경기도 삼척시→강원 삼척시 등)

### [4] 재해유형 분류 기준 명문화 (GPT 재판정 기준 v1 → v2)

- 문제: 기존 데이터에는 분류 기준이 문서로 없음. GPT 1차 판정(v1)에서 "벽체가 무너지며 깔림"을
  기타(무너짐)로 보는 등 원본과 기준이 달랐고, "사다리에서 감전"을 떨어짐으로 추측한 실수도 있었음
- 결정한 기준 (v2)
  1. **사람이 입은 피해의 결과**로 분류한다. 물체에 일어난 일(쓰러짐, 붕괴)이 아니다
  2. 물체·구조물이 쓰러져 사람이 깔림 → **깔림** (쓰러진 것은 물체, 사람은 깔려서 피해)
  3. 토사·굴착면·건물 전체 붕괴로 매몰 → **기타(세부유형: 무너짐)**
  4. 두 가지 이상이 나오면 사람이 다치거나 사망한 **가장 큰 원인**으로 분류
  5. 문장에 없는 내용은 추측하지 않는다
  6. 원본 6종 체계는 유지(V1 비교용)하고, `세부유형`(감전, 무너짐, 익사 등 15종)을 추가해 '기타'의 정보를 보존
- 결과 (원본 라벨과 GPT 불일치): v1 73건 → v2 66건. v1→v2에서 판정이 바뀐 사례 17건
- 다음: 불일치·의심 75건을 사람이 검수해 `최종_유형` 확정

### [5] 매몰과 깔림 구분, 세부유형 → 연관유형

- 문제: 사람 검수 중 "토사 붕괴로 매몰"을 깔림으로 볼지 논의됨. 또 세부유형 칸을
  '주 유형의 구체화'와 '함께 관여한 다른 원인' 두 가지로 쓰게 됨
- 결정
  1. 물체·구조물이 **쓰러져** 사람이 깔림 → **깔림**
  2. 토사·굴착면·건물이 **붕괴해 매몰** → **기타(연관유형: 무너짐)**
  3. 구조물이 붕괴하며 사람이 떨어짐 → **떨어짐(연관유형: 무너짐)**
  4. `세부유형` → **`연관유형`**: 결과에 함께 관여한 원인(계기·후속). 기타일 땐 구체 유형(감전 등). 없으면 주 유형과 같음
- 이유
  - 매몰은 질식 위험이 크고, 구조 방법(추가 붕괴 방지 후 굴착, 호흡 확보)과 예방대책(흙막이 지보공, 굴착면 기울기)이
    깔림(전도 방지, 작업계획서)과 다름. 섞으면 검색 시 엉뚱한 대책이 함께 나옴
  - 공단 재해 발생형태 분류에서도 '깔림·뒤집힘'과 '무너짐'은 별개
  - 6종 체계는 유지해 V1 비교를 공정하게 하고, 연관유형으로 정보 보존
- 결과 (사람 검수 기준, 509건)
  - 원본 라벨 정확도 **87.6%** → **63건(12.4%) 수정**
  - 키워드 규칙 93.3% / GPT v1 96.1% / GPT v2 99.0% (GPT 수치는 검수표에 GPT 판정을 미리 채운 영향으로 상한값)
- 교훈: GPT 성능을 공정하게 재려면, 사람이 GPT 판정을 보지 않고 먼저 라벨링한 표본이 필요함 → 이후 평가에 반영

### [6] V1 재현 방식과 평가 설계

- 문제: V1 코드가 유실되었고, 엑셀 데이터를 GPT에 어떻게 전달했는지 기억나지 않음
- 결정
  1. V1 = **엑셀 사례 전체를 프롬프트에 통째로 넣는 방식**으로 재현 (가장 단순한 형태라고 가정)
     - 데이터는 원본 값 그대로 사용 (원본 라벨·지역·업종). 정제·검증 결과는 V2에서만 사용
  2. 모델은 V1·V2 모두 `gpt-5.4-mini` → 성능 차이를 **데이터와 구조의 차이**로만 해석할 수 있게 함
  3. 테스트셋 100건을 유형 비율대로 층화 추출(시드 42)해 **V1·V2 어느 DB에도 넣지 않음** → 정답 사례를 그대로 찾아 점수가 부풀려지는 것 방지
  4. 테스트 정답은 **블라인드 라벨링**(원본·GPT 라벨을 가린 채 사람이 분류) → [5]의 앵커링 편향 해소
- 관찰된 V1의 구조적 한계 (재현 시 측정)
  - 질문 1개당 입력 약 **50,000 토큰** (사례 409건 전체를 매번 전송) → 비용·응답 시간이 사례 수에 비례
  - SIF 6,032건을 같은 방식으로 넣으면 약 15배 → 모델 입력 한도를 넘어 **확장 불가**
  - → V2에서 '필요한 사례만 검색해서 넣는 방식(RAG)'으로 바꾸는 근거
- 블라인드 라벨링 결과 (테스트 100건)

  | 라벨 | 블라인드 정답 기준 | 이견 조정 후 |
  |---|---|---|
  | 원본 엑셀 라벨 | 89% | 89% |
  | 1단계 검증 라벨 | 96% | 99% |
  | GPT v1 / v2 | 97% / 96% | 97% / 99% |

  - 원본 라벨 오류율 11%: 1단계 전체 측정(12.4%)과 독립적으로 일치 → 기존 데이터 라벨 오류의 근거
  - 블라인드와 GPT가 다른 4건만 사람이 다시 검토해 조정 (사람 실수 2건, 판단 차이 2건). 블라인드 원래 값은 `test_gold.csv`에 보존
  - 연관유형은 둘 이상일 수 있음 (예: 폭발·파열, 맞음) → 쉼표로 구분
- 질문 세트 43개 (아래 [7] 이전 확정): 키워드 10, 상황 설명 10, 사고 대응 8, 통계·조건 6, 데이터 밖 6,
  **실제 V1 시연 질문 3** (Q41→Q42는 이전 대화를 이어받는 질문)

### [7] SIF 수집 결과와 엑셀 데이터와의 관계

- 수집: `collectors/sif_api.py`로 API 61회 호출, **6,032건** (건설업 3,459 / 전업종 2,573). 원본 응답 페이지를 그대로 보존
- 엑셀(509건)과 비교해 얻은 것
  - 사례 수 약 12배, 건설업 외 업종 2,573건 (제조업 1,546, 기타의사업 689, 운수창고통신업 147, 임업 80, 농업 50 …)
  - 기인물(677종), 고위험작업·상황, 재해유발요인, ▶로 구분된 구체적 감소대책
  - 공종·작업명·단위작업명 3단계 분류
- 한계
  - **지역 정보 없음** (장소가 ○○로 익명화) → 지역 검색은 엑셀 사례로만 가능
  - 재해유형이 건설업에만 있고, 체계가 다름(추락·낙하·붕괴·전도 등 14종) → 우리 6종 체계로 재분류 필요
  - 전업종의 재해유발요인은 일반화된 문장이 많음
- 중복·누출 확인: 엑셀 509건과 SIF의 문장 유사도(3글자 단위 Jaccard) 최대 0.39 → 같은 사고 없음.
  테스트 100건이 SIF에 들어 있지 않으므로 **V2 DB에 SIF 전체를 넣어도 평가가 부풀려지지 않음**

### [8] 깔림 기준 보완 (SIF 검증 중 발견)

- 문제: SIF 건설업 원래 재해종류와 GPT 판정을 비교하다가, "깔려"가 들어간 사례 60건이 깔림이 아닌 유형으로
  판정된 것을 발견. 엑셀에서도 같은 흔들림 2건(196·206행 "차량에 깔림" → 부딪힘)
- 결정 (분류 기준 v3.1)
  1. 이동하는 차량·건설기계에 깔림 → **깔림**. 부딪힌 뒤 깔렸어도 깔림 (연관: 부딪힘)
  2. 떨어지는 중량물에 깔림 → **깔림** (연관: 맞음)
  3. 사람이 떨어진 뒤(떨어지면서) 슬라브·자재·장비 같은 무거운 물체에 깔림 → **깔림** (연관: 떨어짐).
     사망의 직접 원인은 깔림이라고 판단. 깔리지 않고 떨어지기만 했으면 기존대로 떨어짐
- 적용
  - SIF: 전체를 다시 돌리지 않고, '깔려/깔림'이 들어 있는데 깔림이 아니었던 60건만 재판정(패치) → 54건 변경
    (부딪힘→깔림 29, 떨어짐→깔림 19, 맞음→깔림 6). 패치 전 유형은 `패치전_유형` 열에 보존
  - 엑셀: 196·206행 → 깔림(연관 부딪힘), 285행 → 깔림(연관 떨어짐). 세 행 모두 DB 쪽이라 테스트 정답에는 영향 없음
- 결과: SIF 원래 유형과 일치율 90.2% → 90.6%
- 남은 불일치의 대부분은 **기준 차이**: SIF는 사건(낙하·붕괴·전도) 기준, 우리는 사람이 입은 결과 기준
  (예: "갱폼과 함께 떨어짐"을 SIF는 낙하, 우리는 떨어짐 / "흔들리는 인양물에 부딪힘"을 SIF는 부딪힘, 우리는 맞음)

### [9] 엑셀 기인물·원인 추출과 통합 데이터셋

- 문제: 엑셀 사례에는 SIF에 있는 기인물·재해유발요인 칸이 없음. 업종 체계도 서로 다름
- 결정
  1. 엑셀 사고 내용에서 GPT로 **기인물·작업·재해유발요인** 추출 (`pipeline/extract_excel.py`).
     **문장에 적힌 내용만** 추출하고 근본 원인을 지어내지 않게 함 → 기인물 미상 4건, 작업 미상 12건
  2. 업종은 SIF 대분류(산재보험 업종) 체계로 통일. 엑셀의 전기공사업→건설업, 철강업→제조업,
     운수·물류·해운업→운수창고통신업, 위생업·문화재 발굴→기타의사업. 원래 값은 `업종_원본`에 보존
  3. 엑셀 + SIF를 한 표로 통합 (`data/processed/cases_v2.csv`, 출처 열로 구분)
- 결과: 검색 DB 409건 → **6,441건**. 기인물·재해유발요인·연관유형 채움률 0% → 100%.
  업종: 건설 3,730 / 제조 1,675 / 기타의사업 692 / 운수창고통신 152 / 임업 81 / 농업 50 / 광업 37 …
- 한계: 시도는 엑셀 사례(6%)에만 있음
