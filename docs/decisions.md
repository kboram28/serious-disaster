# 결정 기록

V1(기존) → V2(개선)로 가면서 내린 결정과 그 이유를 기록한다. 최종 보고서의 "개선 배경" 장으로 사용한다.

---

### [1] 추가 데이터 수집 방식: 크롤링 대신 공공데이터 API

- 문제: 기존 엑셀(공단 재해사례 정리본)에 사고 원인, 기인물, 근거가 없고 건설업 사례에 쏠려 있음
- 선택지
  1. 공단 포털 웹 크롤링
  2. 공공데이터포털 파일 다운로드
  3. 공공데이터포털 오픈 API
- 결정: 3번 오픈 API (SIF 아카이브 조회서비스)
- 이유
  - 이용 조건이 명확함 (이용허락범위 제한 없음, 무료)
  - 크롤링은 사이트 화면 구조가 바뀌면 코드가 깨지고, 이용약관 문제가 생길 수 있음
  - 파일은 갱신될 때마다 직접 다시 받아야 하지만, API는 수집 코드를 다시 실행하면 됨 → "자동 수집" 목표에 맞음
  - 기인물, 고위험작업·상황, 재해유발요인, 위험성 감소대책이 구조화된 필드로 제공됨
- 결과: 6,032건 조회 가능 확인 (건설업 3,459 / 전업종 2,573)
- 남은 과제: 법규·지침 필드가 없음 → KOSHA GUIDE 연결 검토

### [2] 기존 엑셀의 재해유형 라벨 오류: 원본 보존 + 재검증 열 추가

- 문제: 사고 내용의 핵심 단어와 재해유형 라벨이 맞지 않는 행이 51건. 특정 구간에 몰려 있음
  (예: 엑셀 351~358행은 모두 "끼여 사망"인데 라벨은 `떨어짐`).
  사고내용·예방대책은 서로 일치 → 라벨 열(유형·업종·지역)이 구간별로 밀린 것으로 추정
- 영향: 이 라벨을 정답으로 쓰면 분류 정확도 평가가 틀어지고, 업종·지역도 틀렸을 가능성이 있음
- 선택지
  1. 원본 라벨을 그대로 사용
  2. 원본 라벨을 덮어써서 수정
  3. 원본은 보존하고 재검증 라벨 열을 따로 추가
- 결정: 3번
- 이유: V1 재현은 원본 라벨로 해야 공정한 비교가 되고, 무엇을 왜 고쳤는지 추적할 수 있음
- 진행: 키워드 규칙으로 의심 행 표시(`라벨의심`) → GPT 재판정 + 사람 검수로 `유형_검증` 생성 예정.
  업종·지역은 공단 재해사례 API 원문과 대조해 복원 예정

### [3] 지역 표기: 시도 17개 짧은 이름으로 통일

- 문제: 시도 표기가 42종 (`경기`/`경기도`, `서울`/`서울시`, `인천시`/`인천광역시` 등), 오타·사실 오류 포함
- 결정: `서울`, `경기`, `강원` 같은 17개 짧은 이름 + 시군구 열 분리
- 이유: 강원·전북·제주는 특별자치도로 명칭이 바뀌어 긴 이름은 시기마다 달라짐. 짧은 이름은 SIF 등 다른 데이터와 맞추기도 쉬움
- 결과: 시도 표기 42종 → 17종. 오타·오류 10종 수정 (중락구→중랑구, 경기도 삼척시→강원 삼척시 등)
